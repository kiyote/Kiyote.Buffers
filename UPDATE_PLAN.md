# Kiyote.Buffers update plan

This is a review plan, not an implementation. Scope: both production libraries, their tests, benchmarks, and package READMEs. Priorities reflect observed behavior in the current workspace; suspected performance improvements require measurement. Preserve the zero-dependency, low-allocation design and prioritize readable, single-purpose code over speculative abstraction. Breaking public API changes are acceptable **only with documented migration guidance**.

## 1. Fix correctness and safety first

1. **Enforce logical buffer bounds and dimensions consistently.** `FlatArrayBuffer<T>` (`src/Kiyote/Buffers/Kiyote.Buffers/FlatArrayBuffer.cs`) currently indexes `(row * columns) + column` without checking `column`: `[Columns, row]` can alias the next row. `FlatNumericBuffer<T>` and `RaggedNumericBuffer<T>` (`src/Kiyote/Buffers/Numerics/Kiyote.Buffers.Numerics/`) expose their padded columns through the indexer even though `GetRowSpan` excludes them. Reject invalid logical coordinates while keeping fast validated row-span processing. Define a single policy for zero/negative dimensions and checked allocation-size arithmetic in all four buffer constructors and both factory APIs; document it in `IBuffer<T>`, `INumericBuffer<T>` and their READMEs. Tests: first/last valid cell, negative and `Columns`/`Rows` coordinates, zero dimensions, and multiplication/padding overflow for flat and ragged implementations.

2. **Validate every output shape before writing.** `BufferOperator.Perform` (`src/Kiyote/Buffers/Kiyote.Buffers/BufferOperator.cs`) only compares binary operands, not output dimensions. All destination-taking arithmetic, normalization and scaling paths in `src/Kiyote/Buffers/Numerics/Kiyote.Buffers.Numerics/NumericBufferOperator.cs` likewise assume matching dimensions; the ragged vector path can operate on incompatible padded storage. Add shared, small validation helpers outside per-cell loops and define one exception contract (including null operands/delegates as appropriate) across `IBufferOperator` and `INumericBufferOperator`. Verify failures occur **before** any output mutation; cover smaller, larger, and equal-cell-count-but-different-shape destinations for each overload, with both buffer layouts.

3. **Correct numeric normalization and scaling semantics.** `NumericBufferOperator.cs` subtracts `max - min` and `value - min` in `T` before converting to `double` (around lines 450-495); integer extremes can overflow, while integer `Normalize<T>` performs integer division. Define the supported numeric types, precision/rounding, NaN, empty-buffer and constant-buffer behavior in `INumericBufferOperator` before changing the formulas. Use sufficiently wide arithmetic for `ScaleToRange` and specify an appropriate floating-point or explicitly integer normalization contract. Currently constant in-place normalization leaves values untouched, constant out-of-place normalization copies the constant, and constant scaling writes zero. Add tests for `int.MinValue`/`int.MaxValue`, integer and floating-point inputs, constant input, NaNs, and both layouts; do not claim these semantics are interchangeable.

4. **Close coordinate and length overflow paths in chunked grids.** `ChunkedGridLayout.Width/Height` and `TryGetPopulatedBounds` compute extents in `int` (around lines 169-184 and 535-594); widely separated chunks can wrap. `SetPopulatedRun`/`ClearPopulatedRun` increment the column past `int.MaxValue` (around lines 377-423), while `ChunkMap.WalkRuns` translates coordinates in `int`. `ChunkPadding.GetPaddedLength` computes `(size + 2 * halo)^2` unchecked (lines 24-33). Define representable coordinate/extents behavior (checked exception or wider public extent type, documented as an API change), validate **before mutation** where feasible, and use checked/widened arithmetic. Test near both `int` limits, extreme chunk spans, run translation, and oversized padding; ensure no wrapped chunks are allocated.

5. **Make local chunk access and presence invariants explicit.** `GridChunk<T>.IsPopulated` (`src/Kiyote/Buffers/Kiyote.Buffers/ChunkedGrids/GridChunk.cs`, around lines 80-86) can read a different row for an out-of-range local column. Validate public local coordinates, including row accessors as appropriate. For chunk sizes below 64, writable spans from `ChunkedGridLayout.GetPresence/GetPresenceRow` can set bits outside the chunk, distorting `GetPopulatedCount`, `GetFill` and populated bounds. Preserve the documented writable, zero-copy fast path only if a clear valid-bit contract and masking/validation boundary can protect derived results; otherwise replace the writable public surface with a controlled mutation API and explain the migration. Test invalid local columns and manually written high bits for small chunks.

6. **Protect the triple-buffered lease lifecycle.** `TripleBufferedLease<T>` is a copyable readonly struct; `Dispose()` unconditionally calls `Release()`, and `TripleBufferedChunkedGrid<T>.Acquire()` overwrites the outstanding lease marker (`src/Kiyote/Buffers/Kiyote.Buffers/ChunkedGrids/TripleBufferedLease.cs` and `TripleBufferedChunkedGrid.cs`, around lines 83-85 and 100-111). A stale/double dispose can clear a newer lease and let the owner write a buffer still being read. Choose a token/generation or another nonallocating mechanism that rejects an overlapping acquire and ensures only the active lease can release; explicitly define behavior for copied/default/disposed leases. Keep the `Interlocked`/`Volatile` publication handshake intact. Add deterministic stale-release and nested-acquire tests plus cross-thread publication/lease stress tests. Document and, if feasible without hot-path cost, enforce the existing restriction against topology or copy changes while leased.

7. **Handle invalid public grid state predictably.** `DoubleBufferedChunkedGrid<T>.Resolve` and `TripleBufferedChunkedGrid<T>.Resolve` treat every non-`Current` `GridBuffer` value as `Alternate`; reject undefined enum values. `ChunkMap.Attach` aligned fast path creates target chunks for empty source chunks even though unaligned attach only creates for populated runs: decide whether allocated-but-empty chunks should be copied and make both paths match the documented `Attach` contract. `ChunkMap.Layout` is mutable internally: audit every caller for topology changes that could desynchronize `_slots`/`ChunkValues`; restrict mutating access if needed. Add focused enum, empty-attach and topology-invariant tests.

## 2. Improve API clarity and maintainability

8. **Document and test substitutable DI defaults.** Preserve `TryAdd`: an application-provided `IBufferFactory`, `INumericBufferFactory`, `IBufferOperator`, or `IBufferAnalyzer` should take precedence over library defaults. The narrower ambiguity is calling both `AddFlatBuffers` and `AddRaggedBuffers` (`src/Kiyote/Buffers/Kiyote.Buffers/ExtensionMethods.cs`), or both Numerics factory-registration methods (`src/Kiyote/Buffers/Numerics/Kiyote.Buffers.Numerics/ExtensionMethods.cs`): the first registered factory wins. Document that order-dependent default selection; do not reject or replace an existing registration merely because another registration method is called. `Analyzers/ExtensionMethods.cs` also registers a default `IBufferOperator` when `AddBufferAnalyzers` is called; decide whether this convenience is intentional and document it, rather than assuming it violates SRP. Add DI tests for application-supplied substitutes, each default registration, both factory registration orders, and analyzer registration with and without a preexisting operator. Avoid adding interface indirection inside hot loops.

9. **Tighten grid view and enumeration contracts.** `ChunkIndexEnumerator` and related chunk/neighbourhood enumerators check topology changes in `MoveNext`, not necessarily in `Current`; decide whether to enforce the documented invalidation there too or narrow the wording. Buffered chunk views capture buffer roles, so document what happens after `Swap`; verify old views cannot silently masquerade as the new current buffer. `GridChunkNeighbourhood.GetRowValues/GetPresenceRow` select the centre *column* even for halo rows; clarify that behavior in XML docs and test corner-only neighbours. Amend the `ChunkedGridLayer<T>` remark that says `GetReference` can write an unpopulated cell; its implementation throws. Keep any extra checks off proven hot paths unless the contract warrants them.

10. **Refactor only demonstrable responsibility/duplication hotspots.** `ChunkedGridLayout.cs` (~900 lines) combines topology, presence arithmetic, neighbour linking and bounds; `ChunkMap.cs` combines chunk slots with attach/detach traversal; `NumericBufferOperator.cs` (~576 lines) combines vectorized arithmetic, reductions, normalization and `IBufferOperator`. Extract narrow internal helpers only where tests identify duplicated invariants (e.g. presence bit manipulation, numeric reduction tails, repeated run-operation arguments), leaving public zero-copy abstractions and JIT-specialized loops intact. Avoid abstraction layers, boxing, or allocations in per-cell/per-vector paths. Add characterization tests first and compare benchmarks before/after; do not split code merely to reduce file length.

11. **Align documentation with actual supported APIs.** Replace the nonexistent `AddBuffers()` call in `src/Kiyote/Buffers/Kiyote.Buffers/README.md` with the selected factory registration; fix its `%` example's operator precedence and malformed code fence. Its claim that every grid chunk size must be a `Vector256<T>` lane multiple conflicts with `ChunkedGridLayout` accepting power-of-two sizes down to 1; document the distinction between layout-only and typed/value-buffer constraints instead of changing size rules blindly. Replace the Numerics README's `AddNumericBuffers()` example (operator only) with a registration that also provides `INumericBufferFactory`, correct the code fence, and use `INumericBuffer<T>` where required. Correct the nonexistent `analyzer.Evaluate` example in `Analyzers/ICellEval.cs`, qualify pooled steady-state allocation claims in `IBufferAnalyzer`, and describe the conditional thread safety of one-entry read caches in `ChunkMap`/`ChunkedGridLayout` accurately. Record all changed public signatures, exception behavior, naming or factory selection in both package READMEs, with before/after migration examples.

## 3. Establish a regression and performance gate

12. **Broaden targeted test coverage.** Add core flat-buffer and DI tests to `test/Kiyote/Buffers/Kiyote.Buffers.UnitTests`, plus exhaustive chunk bounds, presence mask, overflow, lease and enumerator tests in its `ChunkedGrids` folder. Expand `test/Kiyote/Buffers/Numerics/Kiyote.Buffers.Numerics.IntegrationTests/NumericBufferOperatorTests.cs` to exercise Flat and Ragged for the same operations, destination shapes, element types and factory registrations. Use `Method_Condition_Expectation` for new and touched test names; fix unrelated historical names only when editing those tests. Ensure existing tests still pass after deliberate contract changes.

13. **Measure before accepting hot-path changes.** Compare throughput **and allocated bytes** for core row/indexer operations, analyzer flood fill (small and multi-block), aligned/unaligned grid attach, small and large chunk neighbourhood reads, triple-buffer swap/acquire, and Flat-vs-Ragged numeric arithmetic/reductions/normalize. `FlatNumericBuffer<T>` currently allocates an unused `new T[rows * _allocWidth]` before initializing `_allocWidth`; remove it as a direct allocation fix, then benchmark initialization and whether its padding is useful given that the operator vectorizes Ragged but not Flat. Ensure `BufferAnalyzerBenchmarks` and new triple-buffer scenarios are reachable from the benchmark runner. Record configuration, hardware, baseline and regression thresholds; do not replace spans with delegates/virtual calls inside tight loops to simplify implementation.

14. **Finish with reproducible validation and documentation.** Run a full Release build and both test projects (including new tests), then benchmark changed hot paths and check package README snippets against the real DI registrations. Review `.editorconfig`, `Directory.Build.props`, package dependencies and existing benchmark registration for low-risk cleanups only: remove dead settings/dependencies after checking usage, do not add packages solely to enforce style. Publish an API migration list and benchmark/test results with each implementation phase; any unresolved numerical or lease contract choice must be stated explicitly rather than guessed.

## Acceptance criteria

- No silent aliasing, wrapped coordinates, partial writes on invalid destination shapes, or stale lease releases in the covered scenarios.
- Public bounds, numeric edge cases, topology concurrency limits and factory selection have consistent tests and package documentation.
- No unmeasured throughput or allocation regressions in hot paths; all solution projects build and both test suites pass.
- Public API changes include a concise migration note; internal refactoring preserves responsibilities and minimizes per-cell overhead.

## Review baseline

- Solution build: successful.
- Existing tests: 221 core unit tests and 47 Numerics integration tests passed. These passing tests do not cover the edge cases listed above.
- No benchmark measurements were taken for this review; proposed performance work is conditional on measurements.
